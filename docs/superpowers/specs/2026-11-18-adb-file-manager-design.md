# ADB 手机文件管家 — 设计规格

> 版本 v1.0 · 2026-11-18 · 状态：已确认（多设备形态 A：左侧设备栏 + 全设备总览页）

## 1. 背景与目标

### 1.1 现状痛点

| 现有方案 | 痛点 |
| --- | --- |
| Android Studio Device Explorer | 启动慢（需整 IDE）、不支持拖拽、无预览、传大文件无进度 |
| 命令行 adb pull / push | 路径难记，中文与空格易出错，多设备需反复加 -s |
| AirDroid 等在线方案 | 依赖账号与联网，大文件走中转，隐私顾虑大 |

### 1.2 产品目标

做一款 Windows 桌面端的**安卓手机文件管理器**，插线即用：双栏浏览、拖拽互传、传输队列可视；并支持**多台设备同时管理**——每台设备独立工作区，另有一个总览页做批量操作。

### 1.3 成功标准

1. 插入手机后 3 秒内出现在设备栏并可进入 /sdcard。
2. 1 GB 文件推拉进度与实测偏差 < 3%，可随时取消。
3. 中文、空格、单引号文件名在浏览、传输、重命名全链路正常。
4. 同时连接 3 台设备互不干扰，一台掉线其余任务继续。
5. 安装包 < 120 MB，Win10/11 无额外依赖可运行。

## 2. 范围界定

### 2.1 首版必做（M0–M2.5）

- 设备发现与多设备会话（USB + 无线）
- 远程/本地双栏文件浏览
- 上传、下载、拖拽、传输队列
- 新建、重命名、删除、复制、移动
- 设备总览页与批量推送 / 批量安装 / 批量执行

### 2.2 首版不做（列入 P2/P3）

跨设备直传、双机目录对比同步、断点续传、root 访问、插件系统、macOS/Linux 打包。

> 说明：adb 协议本身不支持断点续传，「续传」需自研分块，成本远高于收益，不做。

## 4. 技术选型

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **Electron + React + TypeScript + Vite** | ✅ 采用 | 主进程可直接 spawn adb 并流式读进度；本机 Node v22 就绪；UI 迭代最快 |
| Tauri + React | 备选 | 包体小，但本机无 Rust 工具链，子进程/流处理生态弱，进度解析要写更多胶水 |
| .NET WPF | 不采用 | 本机无 dotnet SDK，UI 开发效率低，跨平台无望 |

### 4.1 依赖清单

| 用途 | 依赖 | 说明 |
| --- | --- | --- |
| 桌面壳 | electron + electron-builder | 版本在 M0 锁进 package-lock.json |
| 构建 | vite + vite-plugin-electron | 主进程/预加载/渲染层一套构建 |
| UI | react + tailwindcss@3.4 + lucide-react | Tailwind 锁 3.4 保证配置稳定 |
| 状态 | zustand | 按设备分片的天然结构 |
| 虚拟滚动 | @tanstack/react-virtual | 万级目录不卡 |
| 校验 | zod | IPC 入参校验 |
| 配置 | electron-store | 设置持久化 |
| 测试 | vitest | 解析器与队列单元测试 |

### 4.2 adb 来源策略

优先级：用户自定义路径 > 环境变量 ADB_PATH > 随包 platform-tools > 系统 PATH。
随包分发可避免与 Android Studio 自带的 adb 版本打架；启动时做一次版本自检，冲突则提示。

### 5.2 模块职责

| 模块 | 职责 | 不做的事 |
| --- | --- | --- |
| adb/binary | 定位 adb、版本探测、server 健康检查 | 不碰设备业务 |
| adb/client | 带 serial 的命令执行封装，超时与取消 | 不解析输出语义 |
| adb/track | track-devices 长驻流与帧解析 | 不维护设备状态 |
| adb/list-parser | ls -lA 输出 → FileEntry[] | 不发命令 |
| adb/shellsafe | 单引号转义 | 不做业务判断 |
| devices/manager | 设备状态机、会话集合、事件广播 | 不直接操作用户文件 |
| transfer/queue | 按设备分组的任务调度、并发、进度、重试 | 不构造 UI 文案 |
| fs/remote | 目录列表、增删改移（走 adb shell） | 不管队列 |
| fs/local | 本地磁盘读写，路径白名单 | 不越权删系统目录 |
| ipc/handlers | 通道注册、参数校验、错误码转换 | 不写业务逻辑 |

## 6. 多设备会话模型

### 6.1 数据结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| serial | string | adb 唯一标识（USB 序列号或 ip:port） |
| status | device / unauthorized / offline / recovery / unknown | 状态机取值 |
| transport | usb / wireless | 决定图标与带宽策略 |
| model / android / battery / storage | string / string / number / {used,total} | 惰性采集，进设备时拉一次 |
| fileState | { cwd, history, selection, sort, scrollTop } | 每设备独立，切走不丢 |
| queue | TransferQueue | 每设备一个 |

### 6.2 生命周期

1. track-devices 推送新增 → 创建会话，状态 unauthorized/device。
2. 状态变 device → 拉取设备属性（一次 shell 批量取，减少往返）。
3. 设备消失 → 会话标 offline，**保留 30 分钟**；其间进度条置灰、任务标「已中断」。
4. 同 serial 重现 → 复用原会话，恢复 cwd 与选中项，中断任务可一键重试。
5. 超 30 分钟未回 → 释放会话与缓存。

### 6.3 隔离原则

- **所有 adb 命令强制带 -s serial**，AdbClient 构造函数校验，缺 serial 直接抛 E_NO_SERIAL。单设备也走同一路径，杜绝 "more than one device"。
- 设备间事件互不广播：渲染层按 serial 订阅，只接收自己关心的变更。
- 单设备队列故障（断线、目录不可写）只影响本设备。

## 8. 并发与资源策略

| 项 | 值 | 理由 |
| --- | --- | --- |
| 单设备传输并发 | 1（FIFO） | 单 transport 并发 push 互相拖慢，USB 带宽本就独占 |
| 全局并发 | 默认 3，可调 1–6 | 多设备并行才有意义，无线设备更依赖此值 |
| 普通命令超时 | 30s | 防止一台设备卡死拖累全局 |
| 目录列举超时 | 60s | 大目录慢但有上限 |
| 传输超时 | 无硬超时，30s 无输出即判死 | 大文件正常时也可能长时间无输出，用心跳 |
| 事件合并 | ≥ 50ms 合并一次 | 10 设备时避免渲染风暴 |
| 会话保留 | 断线后 30 分钟 | 兼顾快速重插与内存 |

## 10. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 1 万条目录首屏 < 800ms，滚动 60fps；内存常态 < 400MB |
| 安全 | 渲染层零 Node 权限；IPC 白名单 + zod 校验；本地写入限制在用户选定根目录内 |
| 健壮 | 所有 adb 调用有超时与 kill；子进程在窗口关闭时全部回收，不留孤进程 |
| 错误 | 统一错误码 → 中文人话文案；保留原始 stderr 供「复制错误」 |
| 日志 | 写入 userData/logs，按天滚动，默认只记命令与耗时（不记文件内容） |
| 国际化 | 首版中文，文案集中管理，预留 en-US |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 各厂商 ls -l 输出格式差异大 | 列表错乱 | 解析器多分支兼容；失败率 > 20% 时降级逐项 stat；建立样本测试集 |
| 中文/空格/单引号路径 | 命令失败 | 全链路参数数组 + shellQuote 单引号转义 + 专门单测 |
| track-devices 帧格式理解偏差 | 设备发现失效 | 解析器同时兼容「4 位十六进制长度帧」与「裸行」两种形态；失败自动降级 2s 轮询 |
| adb server 版本冲突 | 用户其他调试工具被影响 | 启动自检版本；冲突时提示并允许使用包内 adb 重启 server |
| 大文件进度不准 | 体验差 | 按百分比 × 启动前 stat 的总字节换算；速率用滑动窗口平滑 |
| 多设备 USB 带宽/供电不足 | 频繁超时 | 记录失败率，单设备频繁超时则降并发并提示 |
| 拖入大文件时渲染层卡顿 | 卡死 | 主进程流式读写，渲染层只收事件 |
| 国内安装 electron 慢 | 搭建受阻 | 提供 ELECTRON_MIRROR 环境变量说明 |
| 无权限目录（/data） | 白屏 | 捕获 Permission denied 给人话提示，P2 提供 root 开关 |

## 14. 决策记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| ADR-01 | Electron 而非 Tauri | 本机工具链就绪；adb 子进程流处理更直接 |
| ADR-02 | 多设备形态取「左栏 + 总览页」 | 日常单设备作业空间大，批量场景集中到总览 |
| ADR-03 | 单设备传输并发 = 1，全局 = 3 | 单 transport 并发无收益；多设备并行才有价值 |
| ADR-04 | 不做断点续传 | adb 协议不支持，自研分块得不偿失 |
| ADR-05 | 设备断开保留会话 30 分钟 | 拔插调试是高频动作 |
| ADR-06 | 所有命令强制 -s serial | 从类型层面杜绝多设备误操作 |
| ADR-07 | 随包分发 platform-tools | 规避与 Android Studio 的版本冲突 |
